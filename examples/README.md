# Демонстрация TrafficAI-SUMO

## Запуск

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -E -X utf8 ui/control_panel.py
```

Установка зависимостей описана в [README](../README.md). На чистой копии панель открывает сохранённый московский пример; существующая рабочая модель сохраняет приоритет.

## 1. Район и отчёт

1. Нажмите **«Район и отчёт»**.
2. Выберите два противоположных угла: на карте ПКМ → **«Угол области для отчёта»**. Окно можно временно скрыть крестиком и снова открыть той же кнопкой.
3. Проверьте оранжевую рамку. Границы также можно ввести численно и нажать **«Показать границы»**. Максимум — 25 км².
4. Нажмите **«Сформировать отчёт»**. Во время загрузки работает индикатор. Готовый текст откроется внутри приложения; полная HTML-версия с диаграммой и схемой доступна через **«Открыть HTML в браузере»**. Есть повторное открытие готового отчёта.

Отчёт включает типы и названия объектов, здания неизвестного назначения отдельно, источники и даты. Он не использует LLM и не домысливает население, посещаемость или дефицит инфраструктуры. Overpass может отвечать медленно; предусмотрен резервный OSM API. При ошибке выводится причина.

Готовый пример: [инфраструктура Покровки](moscow/area/report.html).

## 2. Светофорные планы

1. Нажмите **«Светофорные планы»**: загрузится текущая рабочая конфигурация либо московский пример. Можно выбрать другой `.sumocfg`.
2. Задайте границы:

| Интервал | Минимум | Максимум |
|---|---:|---:|
| Непрерывный зелёный | 15 с | 60 с |
| Непрерывный жёлтый | 3 с | 5 с |
| Непрерывный красный направления | 10 с | 90 с |
| Фаза «всем красный» | 1 с | 3 с |

Для московского примера цикл **82 с**. Можно оставить загруженный цикл; поколений **3**, вариантов **8**, зерно **42**. Показанный сохранённый план: зелёный **30 с**, жёлтый **3 с**, красный **49 с**, общий красный **1 с**. Части зелёного 25+5 с в таблице фаз относятся к одному непрерывному сигналу; разделение связано с пешеходами.

3. Нажмите **«Подобрать план»**, затем **«Открыть отчёт»** и **«Результат в SUMO»**. В SUMO нажмите зелёный треугольник запуска.

Пешеходные и защитные исходные минимумы не сокращаются; проверка учитывает границу цикла и шаг SUMO. Несовместимые настройки отклоняются. В исходной нерегулируемой модели отдельно доступно **«Создать регулируемый вариант»**; московский пример уже содержит программу.

Готовые файлы:
- [Исходная московская модель](moscow/model/scenario.sumocfg).
- [План с проверкой ограничений](moscow/plans/optimized/report.html).
- [Запускаемый результат SUMO](moscow/plans/optimized/scenario.sumocfg).

В сохранённом примере допустимый исходный план сохранён без улучшения. Само соблюдение ограничений не означает, что удалось уменьшить очереди.

## 3. RL-обучение

1. Нажмите **«RL-обучение»**, задайте диапазоны и число эпизодов.
2. Нажмите **«Начать обучение»**. Журнал показывает прогресс, доступна остановка.
3. После завершения результаты открываются внутри приложения; политика и JSON сохранены в отдельной папке `runs/rl_training_…`.

RL использует отдельную учебную сеть без пешеходов, не московскую модель. Red здесь означает «всем красный». Результаты сравниваются с двумя фиксированными планами на нескольких seeds, улучшение не гарантируется. [Сохранённое сравнение](rl_result/report.html).

## Воспроизводимость

Команды из корня репозитория:

```powershell
sumo -c examples/moscow/model/scenario.sumocfg --no-step-log
.\.venv\Scripts\python.exe -E -X utf8 -m sumo.signal_plan --config examples/moscow/model/scenario.sumocfg --output runs/plans --generations 2 --population 4
.\.venv\Scripts\python.exe -E -X utf8 sumo/rl_signals.py --backend libsumo --episodes 2 --evaluation-seeds 2 --output runs/rl
.\.venv\Scripts\python.exe -E -X utf8 -m unittest discover -s tests -v
```

Для RL без libsumo используйте `--backend traci`. Свежие запросы карты требуют интернета. Рабочая модель, отчёты и результаты сохраняются локально; публикация на GitHub автоматически не выполняется.
